v1.1.218 - 수동 와이어 밀기 프로파일을 식은/뜨거운 두 개로 분리

■ 문제
v1.1.208 에서 맞춘 값은 식은 상태 기준이었다.
용접 직후 뜨거운 상태에서 재보니 과송급된다.

  요청 5mm  -> 실제 8mm   (명령 1068ms)
  요청 25mm -> 실제 31mm  (명령 4117ms)

■ 역산
  속도 = (31 - 8)mm / (4117 - 1068)ms = 7.54mm/s
  지연 = 1068ms - (8 / 7.54) * 1000 = 7ms

                지연      속도
  식은 상태     306ms   6.56mm/s
  뜨거운 상태     7ms   7.54mm/s

뜨거우면 라이너 마찰이 줄어 모터가 바로 돌고 더 빨리 나간다.
지연이 거의 사라지는 것이 특징이다.

한 프로파일로는 못 덮는다.
  식은 값으로 맞추면   뜨거울 때 25mm -> 31mm
  뜨거운 값으로 맞추면 식었을 때 25mm -> 20mm

송급에 엔코더가 없어 실제 길이를 되먹임할 방법이 없으므로 상태로 나눈다.

■ 수정
robot-front/src/lib/wireFeed.ts

  WIRE_FEED_PROFILE_COLD  밀기 306ms / 6.56mm/s
  WIRE_FEED_PROFILE_HOT   밀기   7ms / 7.54mm/s
  WIRE_HOT_WINDOW_MS      5분

아크 OFF 시각을 localStorage 에 남기고(markArcOff), 그로부터 5분 안이면
뜨거운 값을 쓴다. 세 화면(작업 툴바 / 와이어 조정 팝업 / 팬던트)이 모두
wireFeed.ts 를 쓰므로 한 번에 반영된다.

markArcOff 호출 위치
  weaveHelpers.ts   safeArcOff (파트마다)
  weldingExecution.ts  전체 종료 후 arcOff

5분은 임의로 잡은 값이다. 실제로 몇 분이면 식는지 확인되면 바꾼다.

■ 당기기
두 상태 모두 재지 않았다. v1.1.160 값(220ms / 23.4mm/s)을 양쪽에 그대로 쓴다.

■ 주의
localStorage 는 브라우저별로 따로 남는다. 프로그램을 새로 설치하거나
브라우저 데이터를 지우면 식은 값부터 다시 시작한다.
