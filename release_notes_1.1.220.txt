v1.1.220 - 상태 폴링이 작업을 멈추게 하던 문제 수정

■ 증상
2026-10-06 펜던트. 터치센싱이 갈수록 느려지다가 중간에 멈추고
화면에 "Robot Core에 연결할 수 없습니다"가 떴다. 로봇과 robot_core.exe는
둘 다 살아 있었고, 비상정지만 즉시 먹혔다.

■ 원인
두 가지가 겹쳤다.

1) 브라우저 연결 고갈
   /robot_sdk/realtime을 네 곳에서 각자 폴링한다.
     - components/layout      헤더 로봇 상태 표시
     - useRobotControl        교시 폴링
     - usePathTracking        경로 추적
     - UcellSelect            공구좌표 확인
   응답이 늦어지면 이 요청들이 pending으로 쌓인다. 브라우저는 같은 출처에
   동시 연결을 6개까지만 쓰므로, 쌓인 폴링이 연결을 다 먹으면 터치센싱이나
   이동 명령을 보낼 연결이 남지 않는다. 현장 Network 탭에 realtime 요청이
   10개 이상 pending으로 깔려 있었다.
   타임아웃이 60초라 막힌 요청 하나가 연결을 1분씩 붙잡았고,
   타임아웃이 날 때마다 포트 재감지가 돌아 /system/version 요청이
   최대 3개씩 더 나가면서 상황을 키웠다.

   창을 최소화하면 브라우저가 타이머를 스로틀링해 폴링이 거의 멈추므로
   터치센싱이 정상 속도로 돌았다. 다시 띄우면 같은 상태로 돌아갔다.

2) robot-core의 /robot_sdk/robot/error가 m_mutex를 잡았다
   이 핸들러가 getState()를 불렀다. getState()는 m_mutex를 잡고
   GetRobotRealTimeState()를 직접 호출하는데, 컨트롤러 응답이 늦으면
   그 SDK 호출이 mutex를 쥔 채 매달린다. 그동안 이동/터치센싱 명령은
   전부 뒤에서 대기한다. 비상정지만 멀쩡했던 건 그 경로가 mutex를
   쓰지 않기 때문이다.

■ 수정
robot-front/src/lib/robotApi/index.ts
  - getRealtimeRobotStatus / getRobotError에 요청 공유(in-flight) 추가.
    이미 날아간 요청이 있으면 새로 보내지 않고 같은 응답을 나눠 쓴다.
    호출부를 건드리지 않고 동시 요청이 항상 1개로 제한된다.
  - 두 요청의 타임아웃을 60초에서 4초로 축소.

robot-front/src/lib/http.ts
  - 타임아웃(ECONNABORTED/ETIMEDOUT)을 포트 재감지 대상에서 제외.
    타임아웃 1건이 추가 요청 3개를 부르던 증폭을 끊는다.

robot-core/src/robot_core_all.cpp
  - /robot_sdk/robot/error가 getState() 대신 getCachedState()를 쓴다.
    mutex도 SDK 호출도 타지 않는다. 캐시는 monitorLoop가 50ms 주기로
    갱신하므로 에러코드 신선도는 그대로다.

■ 확인 방법
터치센싱 중 F12 Network 탭에서 realtime 요청이 1개를 넘겨 쌓이지 않으면
정상이다. 창을 띄워 둔 상태와 최소화한 상태의 속도가 같아야 한다.


■ 펜던트 화면 기능 추가
작업 저장
  지금까지 펜던트에는 "작업 불러오기"만 있고 저장이 없었다. 포인트를 다시
  잡아도 DB에 남길 방법이 없었다. 좌상단에 "작업 저장" 버튼을 추가했다.
    - 작업을 불러온 상태면 "현재 작업에 덮어쓰기 / 새 작업으로 저장"을 고른다.
    - 고른 작업이 없으면 바로 새 작업으로 저장한다.
    - 새 작업 이름은 자동(작업_날짜시간). 펜던트는 터치 전용이라 이름 입력을
      받지 않는다.
  덮어쓰기는 PUT /teaching/jobs/{id}를 쓴다. 작업이 새로 생기지 않으므로
  목록이 늘어나지 않는다.
  useJobManagement에 overwriteJob을 추가했고, saveJob과 포인트 변환 로직을
  buildPointsData로 공유한다. UcellSelect 동작은 그대로다.

터치센싱 버튼
  훅(useWeldingHandlers.handleStartTouchSensing)에는 이미 있었는데 펜던트
  화면에만 버튼이 없었다. 우측 도크 "용접 시작" 위에 추가했다.
  용접 시작과는 별개로 터치센싱만 따로 돌릴 수 있다.
  (용접 시작 시 자동 터치센싱은 넣지 않았다. 터치센싱 동작을 진단하는
   중이라 따로 돌릴 수 있어야 한다.)
