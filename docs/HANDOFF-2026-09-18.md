## 핵심 규명 사실 (9/17)

**P9 시작 불량의 원인 — 터치 보정 누락 (154에서 수정).** 좌측 수평 → 우측 수직(p6→p9) 전환만 별도 분기를 타는데, P9로 가는 MoveL이 `offsetFlag=0`이라 티칭 좌표 그대로 이동했다. 9/17 실측으로 토치가 접합부에서 25~28mm 떨어진 채 아크를 켰고, 용접기가 모재에 닿을 때까지 와이어를 내보내 와이어가 길어지고 시작부가 뭉쳤다.

| 세트 | P9 보정값(depthOffset 반영) | 떨어진 거리 | P9 점화 시간 |
|---|---|---|---|
| 1.1.152 (9/17 14:44) | dx −13.2 / dy +17.4 / dz −11.6 | 약 25mm | 2.1초 |
| 1.1.153 (9/17 16:13) | dx −14.3 / dy +21.8 / dz −11.2 | 약 28mm | 2.9초 |

다른 시작점의 정상 점화는 약 1.3초(프리플로우 500 + 대기 500 + 점화). 도입 시점은 `HANDOFF.md` §3-7의 v1.1.98 기록이 유일한 근거 — 9/11 복구 스냅샷(`f04371a`)에 묻혀 git으로는 추적 불가.

**와이어 스틱아웃.** 9/17 실측: 수직 종료 후 수평 시작 15mm, 수평 종료 후 P9 시작 50mm(목표 25mm). 인칭 실측(와이어 인칭 화면 5.0mm = 모터 ON 2857ms, 1회당): 밀기 +27.3mm(3회 평균, ±1), 당기기 −73.0mm(3회 평균, ±1). 571ms 당기기는 −10mm → 모터 지연 약 210ms, 지연 후 속도 밀기 약 10.3mm/s, 당기기 약 27.5mm/s. 코드 상수 `WIRE_FEED_SPEED_MM_PER_SEC = 1.75`는 실제와 크게 다름 — **와이어 인칭 화면의 mm 표시는 실제 길이와 맞지 않는다.**

- 155의 `[AnalogIn]` 로그는 확인용 — 끝나면 제거 가능.

## 사용자 작업 방식

한 번에 한 주제. 수정은 승인받고 진행. 답변은 짧게, 이모지 없이, 존댓말 한국어. 명령은 PowerShell 기준(`&&` 금지), `.bat`는 PowerShell에서 실행. 코드 수정·버전업 후엔 빌드~릴리즈 명령까지 바로 제시. 버전 번호는 추측하지 말고 파일에서 확인. 요청 안 한 제안·다음 단계 늘어놓지 말 것. **용접이 도는 중에 현장에서 직접 측정해 달라는 요청은 하지 말 것 — 로그와 사진으로 판단한다.**
