## 핵심 규명 사실

**끝점 평균 보정 버그 (149에서 수정).** 9/16 좌측 수직 상단 불량 원인. P1 실측 (2.10, -7.38) vs 적용 평균 (-3.91, -3.26) → 끝점 오차 6.0/4.1mm. 9/15 좌측 2.0/2.8mm, 우측 0.6~1.1mm. 경유 방식(per_point)은 **용접 중 멈춤 문제**로 실용접에서 쓰지 않기로 함 — 단일 MoveL 유지.

**P2 측정 치우침(미확인).** 좌측 수직 P2 실측이 P3–P1 직선에서 dy로 약 6mm씩 벗어남(9/15 6.4, 9/16 6.1). 토치 각도(rx≈155°) 차이에 따른 측정 치우침으로 추정. 149 적용 후 **중간 높이 비드**를 볼 것.

**터치 보정값은 메모리에만 있음.** DB에 저장 안 됨(`useAutoSavePoints`에 없음). 작업 재로드/화면 이동/앱 재시작 시 사라짐 → 9/16 수평 용접이 보정 없이 진행됨. **터치센싱 후 화면 이동 없이 바로 용접**할 것. 근본 해결(DB 저장)은 미착수.

**터치센싱 동작.** 탐색은 티칭점에서 시작, 축마다 접촉 후 10mm 후퇴(`touch_sensing_retract_distance`). 앱이 수직 X·좌측 Y에 +5, 우측 Y에 -5(depthOffset) 더함, 수평은 안 더함. 반복 정밀도 0.5mm 이하(9/17 확인). **와이어 길이/휨이 바뀌면 전 포인트 값이 같이 틀어짐**(9/17 휜 와이어로 dz 약 10mm 차이). 9/17 좌측 수직에서 기존 비드에 토치가 닿음 → 새 작업물에서 재확인 필요.

**미접촉 시 동작.** 탐색거리 끝까지 가면 로봇 에러 7-14(와이어 탐색 시간 초과), 이후 모든 명령 code=14로 거부. 에러 초기화 필요. 150 이전엔 이 거리(-50)가 보정값으로 저장됐음.

**작업 자동 로드 버그 (151에서 수정).** 생성일 최신 작업을 로드했고, `handleLoadJob` 의존성 때문에 사용 중에도 재실행돼 작업이 바뀌고 보정값이 지워질 수 있었음.

## 아크 트래킹 (보류, 켜기 전 확인 사항)

순서: 기준선 확보(트래킹 OFF) → AI 채널 확인 → 트래킹 ON 비교. 차장님께 AI 배선 건 보고 예정/진행.

**전류 피드백 배선이 필요.** 아크 트래킹은 실제 용접 전류를 읽어야 동작.
- Dex2 매뉴얼 4.21 DB25: **11번(보라2) 실제 전류 피드백**, 13번(파랑1) 아날로그 GND, 14번(파랑2) 실제 전압 피드백, 12번 전류 지령, 15번 전압 지령.
- 컨트롤 박스 단자대(위 플러그): 바깥 줄 17·18·19 = GNDA·AO0·AO1 에 초록·보라·갈색 연결됨(케이블 색은 매뉴얼 색과 다름). 안쪽 줄 AI0·AI1(SDK 채널 4·5)에는 선이 **안 보임** → 배선 없을 가능성 높음(미확정).
- 확인: WebApp I/O에서 AI0/AI1 값 띄우고 짧게 아크 ON → 값이 안 움직이면 배선 없음.
- 배선 시: DB25 11 → AI0(또는 AI1), 13 → GNDA, 컨트롤 박스 딥스위치 AI를 전압(0~10V)으로, SDK `ArcWeldTraceAIChannelCurrent` / `ArcWeldTraceCurrentPara` 또는 WebApp에서 채널·환산 설정(우리 코드엔 호출 없음).
- **피드백 출력 범위(몇 V = 몇 A) 미확인.** 매뉴얼 표의 Note 4~9가 누락. 용접 중 11–13번 전압 측정 또는 Megmeet/공급처 문의.

**FAIRINO 아크 트래킹 가이드(사용자 제공 이미지) 요점.**
- 부호: 보정 방향이 좌표계 +Z와 같으면 양수. 툴/베이스 좌표계는 매뉴얼 예시에서 **음수**, **스윙 좌표계는 Z가 반대라 양수**. → 스윙(0)+양수(Lua)가 매뉴얼과 일치. 툴(1)+양수(이전 설정)는 반대일 가능성.
- 보정 시작/샘플링 시작(cyc)은 아크 후 3~4초: 위빙 1Hz→4, **2Hz→8**. 샘플링 횟수 기본 1.
- 상하 보정은 위빙 없이도 가능(이때 툴/베이스). 좌우 보정은 **평면 삼각파/사인파 위빙에서만**. 수직 위빙 type 6(수직 삼각파)은 좌우 보정 대상 아님 → 수직에서 좌우 끌 것 검토.
- 적용 조건(상하+좌우): 주파수 0.5~2Hz, 진폭 3~7mm, 전압>19V, 전류>210A — 현재 조건 충족.
- 궤적-용접선 편차 ≤100mm/m. 순서: 트래킹 ON → ARCStart → WeaveStart → 이동 → WeaveEnd → ARCEnd → 트래킹 OFF(우리 코드와 동일).
- 매뉴얼은 CANopen+PLC 구성(피드백을 통신으로 받음), 필터 F18=20/F19=56은 ArtsenII 기준 — Dex2 해당 여부 모름. 웹 V3.6.9 이상 필요(현재 3.9.8).

**첫 테스트 때 재검토:** 최대 보정 5/300 → 1/10으로 좁힐지, 수직 좌우 보정 끌지, 시작/샘플링 4 → 8(2Hz).

**Lua 참고(이전 담당자).** 수직만 위빙과 함께 트래킹 사용. 우측 수직 종료 시 `ArcWeldTraceControl(1,...)`로 **안 끄는 버그**, 파일 상단 `DryRun=true`. 트래킹이 실제로 잘 됐는지는 모름. DryRun 시 용접 전 와이어 역송급 1초, 전체 종료 후 정송급 0.8초.
