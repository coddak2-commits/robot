# 터치센싱 동작과 설정값 (2026-09-16)

같은 오해가 반복돼서 정리한다. 핵심은 **어프로치 오프셋과 탐색 거리는 서로 독립**이라는 것.

## 한 포인트의 동작 순서

```
이전 위치
  │
  ├─ ① 어프로치   티칭점 + 오프셋 위치로 이동        offsetFlag = 1
  │                (p9/p10은 로컬 -Y, 나머지는 +X)
  │
  ├─ ② 정확 위치  티칭점으로 이동                   offsetFlag = 0
  │                ← 탐색은 여기서 시작한다
  │
  ├─ ③ 탐색 1     닿을 때까지 전진 → 접촉 → 10mm 후퇴
  ├─ ③ 탐색 2     (축이 여러 개면 반복, 어프로치는 다시 안 함)
  │
다음 포인트
```

## 설정값의 의미

| 설정 | 의미 | 기준점 |
|---|---|---|
| `touch_sensing_approach_offset` | ①의 경유점이 티칭점에서 얼마나 떨어져 있는지 | 경로용 |
| `touch_distance` | ③에서 티칭점부터 최대 몇 mm까지 찾을지 | 측정용 |
| `touch_sensing_retract_distance` | 접촉 후 다음 축 탐색을 위해 물러나는 거리 | |
| `touch_sensing_home_retract_offset` | 마지막 포인트에서 홈 복귀 전 후퇴 거리 | |

## 자주 하는 오해

**"어프로치 오프셋이 탐색 시작 위치다"** — 아니다. ①로 떨어진 곳에 갔다가 ②에서
다시 티칭점으로 붙는다. 탐색은 항상 티칭점에서 시작한다.

**왜 그래야 하나.** 터치센싱이 구하는 값은 `delta = 접촉 위치 − 탐색 시작 위치`이고,
이 값이 그대로 용접 보정량이 된다. 탐색이 어프로치 지점에서 시작하면 delta에 어프로치
거리가 통째로 섞여 보정량이 그만큼 틀어진다. 어프로치를 바꿀 때마다 보정량도 같이
움직이게 된다.

**실측 근거.** 어프로치를 25 → 50mm로 바꿨는데 delta는 그대로였다.

| | 어프로치 25mm (9/15) | 어프로치 50mm (9/16) |
|---|---|---|
| dx delta | -12.9 ~ -18.3 | -8.7 ~ -15.5 |
| dy delta | 13.0 ~ 18.9 | 19.3 ~ 24.1 |

**"두 값이 같으면 탐색이 티칭점에서 끝난다"** — 아니다. 탐색은 티칭점에서 *시작*해서
거기서부터 `touch_distance`만큼 더 간다. 50/50이면 티칭점 너머 50mm까지 찾는다.

## 값을 정하는 기준

**어프로치 오프셋** — 경로만 바꾼다. 멀수록 진입 방향이 확실해지지만, 경유점을 만들기
위해 관절이 더 꺾일 수 있다(2026-09-16 p7에서 홈 복귀 후퇴 100mm 때 발생).
간섭이 없다면 굳이 늘릴 이유가 없다.

**탐색 거리** — 실측 접촉 거리의 2배 정도가 적당하다. 실측이 8~24mm이므로 50mm면
충분하다. 늘리면 접촉을 못 찾았을 때 티칭점 너머로 그만큼 더 밀고 들어간다.

현재값: 어프로치 50 / 탐색 거리 50.

## 구현 메모

- 탐색 거리는 v1.1.146까지 `LUA_SEARCH_DIS = 30.0f`로 하드코딩돼 있었고
  `touch_distance` 설정은 로그에만 찍혔다. v1.1.147에서 연결했고 10~100mm로 제한한다.
- 탐색 이동은 `moveL(..., search=1)`로 나가고, 컨트롤러가 접촉을 감지해 정지시킨다.
  목표 좌표로 가는 게 아니라 닿을 때까지 미는 동작이라 오프셋 개념이 없다.
- FAIRINO 매뉴얼 W-Search의 "서치 거리"(p.370, 0~1000mm)가 `touch_distance`에 해당한다.
  매뉴얼의 "최대 탐사 거리 0~100mm"는 힘/토크 센서를 쓰는 FT_FindSurface(p.380)의
  값이고 현재 코드와 무관하다.
