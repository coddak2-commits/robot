v1.1.228 - 모서리 파트 분리 (한 변당 3파트)

(2026-10-07 정정: 이 빌드에 담긴 범위는 아래 1~5번까지다. 빌드 뒤에 추가로
 고친 블록 파라미터 적용·모서리 기본값·화면 표시는 v1.1.229 로 넘어갔다.)

[배경]
모서리 비드 아래쪽이 채워지지 않는 문제가 1.1.202 이후 계속 남아 있었다.
시작 체류(202~204)와 기어가기(205~213)를 모두 시도했으나 해결되지 않았다.
원인은 위빙 폭이 파트 단위로만 설정된다는 것이다. weldingExecution 은 파트
시작 시 setupAndStartWeave 를 한 번만 호출하고 파트 중간에 WeaveSetPara 를
다시 보내지 않는다. 게다가 WeldBatch 가 파트를 끝점까지 MoveL 하나로 접기
때문에 같은 파트에 포인트를 더 넣어도 통과점이 될 뿐이다.
모서리 20mm 만 위빙 폭과 속도를 따로 주려면 그 구간이 별도 파트여야 한다.

[구성 변경]
포인트 수는 12개 그대로. 수평의 중간점을 없애고 그 번호를 모서리로 옮긴다.

  P3  모서리에서 위로 20mm   (재티칭)
  P4  모서리 (수직선 바닥)   (변경 없음)
  P5  모서리 (수평선 시작)   (재티칭, 기존 P4 자리)
  우측은 P9, P11 이 같은 방식으로 재티칭 대상이다.

실행 순서: 수평(P5-P6) -> 모서리(P4-P3) -> 수직(P3-P2-P1) -> 우측 동일.
이 순서라야 모든 아크 시작이 이미 쌓인 금속 위에 떨어지고, 로봇의 복귀 이동도
늘어나지 않는다.

파트 구성 자체는 DB(welding_part_order)에 있다. database/migrations/
012_corner_part_split.sql 을 각 기계에서 실행해야 적용된다.
되돌리기는 012_corner_part_split_rollback.sql.

[코드 변경]
1. 크레이터 판정 기준 변경 (weldingExecution.ts)
   1.1.227 의 수직 번호 목록(1,2,3,7,8,9)은 수직 파트가 P1/P7 에서 끝나던
   구성에서만 맞는 식이었다. 모서리 파트를 넣으면 그 파트 끝 P3/P9 가 목록에
   걸려 크레이터가 돌고, 수직이 같은 자리에서 바로 이어받는데 거기 1.6초를 더
   쌓아 개선선 중간에 덩어리가 생긴다.
   한 셀에서 비드가 실제로 끊기는 자리는 수직 위쪽 끝 둘(P1/P7)뿐이므로
   CRATER_END_POINT_IDS = ['p1','p7'] 로 좁혔다.

2. NEAR_UCELL_CORNER 에 p11 추가 (weldingExecution.ts)
   우측 수평 시작점이 p10 자리로 옮겨간다. 그 자리는 U셀 구조물과의 간섭으로
   base +X 접근 시 충돌(code=185)이 나서 -Y 로 접근해야 한다. p11 을 빼면
   우측 수평 시작에서 185 가 난다.

3. 파트 시작 체류에 p5/p11 추가 (weldingExecution.ts)
   수평 시작점이 P4/P10 에서 P5/P11 로 옮겨간다. P4/P10 의 1000ms 는 그대로
   둔다. 이제 모서리 파트의 시작점이고 그 자리가 채우려는 모서리다.
   결과적으로 모서리에는 수평 시작 체류 1초 + 모서리 시작 체류 1초가 들어간다.
   과하게 쌓이면 P4/P10 쪽을 먼저 줄일 것.

4. 펜던트 화면 (pages/pendant/index.tsx)
   - SEGMENTS: 모서리 구간(P4-P3, P10-P9) 추가. 수평은 P5-P6 / P11-P12.
     갭은 세그먼트 startId 포인트에 저장되므로 모서리 갭은 P4/P10 에 들어간다.
   - PART_GAP_MAP: 6개로. 모서리 항목에서 P3/P9 를 빼고 수직 항목을 모서리보다
     앞에 뒀다. P3/P9 는 수직 파트의 '첫 포인트'이고 파트 파라미터는 첫 포인트에서
     읽히므로, P3/P9 에는 반드시 수직 파라미터가 들어가야 한다.
   - getPosture: 4/10 추가. 모서리는 수직선을 타는 용접이라 갭 파라미터도 수직
     테이블을 조회해야 한다.

5. 패스 체크박스 묶음 분리 (UcellSelect/index.tsx)
   체크박스는 화면상 4개 고정이고 실행 파트는 DB 에서 6개가 온다. 파트 -> 체크박스
   키 역산을 227 까지는 DEFAULT_WELDING_PARTS 로 했는데, 그것은
   welding_part_order 가 비었을 때의 '실행 기본값'이기도 해서 묶음을 바꾸려고
   손대면 실행 경로가 같이 바뀐다. PART_ENABLE_GROUPS 를 따로 두고 두 역할을
   분리했다. 판정도 some -> every 로 바꿨다(파트 전체가 한 묶음에 들어가야 한다).

   모서리는 수직과 같은 묶음이다.
     0: 수평 좌 (P5-P6)
     1: 수직 좌 + 모서리 좌 (P1-P3, P4)
     2: 수평 우 (P11-P12)
     3: 수직 우 + 모서리 우 (P7-P9, P10)

   주의: 수평만 끄고 돌리면 모서리 파트가 아크를 켜는 자리(P4/P10)에 수평 비드가
   없다. 차가운 맨 모서리에서 시작하므로 시작부가 얇게 깔린다.

[변경하지 않은 것]
DEFAULT_WELDING_PARTS(4개)는 그대로 둔다. welding_part_order 가 비었을 때의
실행 기본값이다. 012 적용 후에는 DB 가 6파트를 주므로 평소에는 쓰이지 않는다.
DB 읽기가 실패하면 모서리 파트가 빠진 4파트 경로로 돌아 바닥 20mm 가 안 깔린다
(충돌은 나지 않는다). 로그 welding.partOrder 에 파트가 6개인지 매번 볼 것.

펜던트 PART_CHECKBOXES 는 4개 그대로다. 위치는 partCheckboxPos 가 partIdx 로
직접 계산하고 라벨은 '용접'/'패스' 뿐이라 묶음이 바뀌어도 손댈 것이 없다.

[적용 절차]
1. DB 백업: mysqldump --result-file=... robot_welding
2. 012_corner_part_split.sql 실행
3. P3/P5/P9/P11 재티칭 후 '작업 저장'(덮어쓰기 아님)으로 새 작업 생성
4. P4/P10 에 넓은 위빙 파라미터 입력 (모서리 파트의 첫 포인트)
5. 펜던트와 노트북 DB 는 별개이므로 각 기계에서 1~4 를 각각 수행

[현장 확인 항목]
- 로그 welding.partOrder 에 6개 파트가 찍히는지
- welding.partEnd.crater 가 P3/P9/P6/P12 에서 '생략(이어짐)'인지
- 우측 수평 시작(P11)에서 충돌(code=185)이 없는지
- 모서리 비드 아래쪽 충전 상태 (이번 변경의 목적)
