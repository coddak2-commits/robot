v1.1.230 - 모서리 파트 분리 후속 점검 (충돌 회귀 · 모서리 속도 · 중심선 방향)

v1.1.228/229 를 코드 리뷰한 결과 세 건을 고친다. 1번은 충돌 위험이라 229 로는
현장 실행을 하지 말 것. 2번은 모서리 파트를 만든 목적 절반이 작동하지 않던 건이다.

[1] P12 -> P10 전환에서 코너 접근 보호가 빠졌다 (충돌 위험, 228 회귀)
    weldingExecution.ts

    파트 전환 ②에서 isSameSide 분기가 NEAR_UCELL_CORNER 분기보다 먼저 걸린다.
    같은 쪽 전환이면 목표가 코너여도 base +X 로 진입한다. 이 구조 자체는
    v1.1.175 부터 그대로다.

    227 까지 P10 에 들어가는 경로는 P1 -> P10 횡단 하나뿐이었다. 횡단은
    isSameSide 가 false 라 코너 분기를 타고 홈 경유 -Y 로 진입했다. 즉 P10 에
    +X 로 들어간 적이 한 번도 없었다.

    228 에서 수평을 앞으로 빼면서 실행 순서가
      ... [P11,P12] -> [P10,P9] ...
    가 됐고, 12 와 10 이 둘 다 우측이라 같은 쪽 전환이 됐다. 그 결과 P10 에
    base +X 로 진입한다. 703행 주석이 바로 그 자리를 "p9/p10 은 base +X 접근 시
    충돌(code=185) 확인됨" 이라고 적어둔 곳이다.

    참고: 227 에서 P12 -> P9 도 같은 쪽 전환이라 P9 에는 +X 로 들어갔고 현장에서
    문제가 없었다. 다만 228 재티칭으로 P9 는 모서리에서 20mm 위로 올라가고 P10 만
    모서리에 남으므로, 그 선례가 P10 을 보증하지 못한다.

    수정: 목표가 NEAR_UCELL_CORNER 포인트면 isSameSide 를 false 로 둔다.
    그러면 P12->P10 과 P9->P9 가 '후퇴 -> 홈 경유 -> -Y 직선 진입'으로 간다.
    둘 다 227 에서 돌던 경로다(P10 은 횡단 진입, P9 는 시작점 진입).
    대가는 셀당 홈 경유 2회 추가다.

[2] 배치 이동 속도가 파트 첫 포인트가 아니라 두 번째 포인트에서 읽혔다
    weldingExecution.ts

    robot-core 의 WeldBatch 는 배치 첫 포인트의 speed/vel_mode 만 읽는다
    (robot_core_all.cpp 의 `float speedRaw = firstPt.value("speed", ...)`).
    그런데 프런트는 파트 시작점을 전환 분기에서 따로 처리하고 i++ 하므로, 배치는
    항상 파트의 두 번째 포인트부터 만들어진다. 결과적으로

      아크 조건(전류·전압·위빙) <- 파트 첫 포인트
      이동 속도                 <- 파트 두 번째 포인트

    로 갈려 있었다. 227 까지는 갭 조회가 파트 단위로 같은 값을 넣어서 드러나지
    않았다. 228 에서 모서리를 [P4,P3] 두 점짜리 파트로 떼면서 문제가 됐다.
    배치가 [P3] 하나뿐인데 P3 는 수직 파트의 시작점이기도 해서 갭 조회가 수직
    파라미터를 넣는다. 그래서 P4 에 모서리용 느린 속도를 넣어도 먹지 않고
    모서리 20mm 가 수직 속도로 돌았다. 012 마이그레이션이 적은 목적
    ("모서리 20mm 만 위빙 폭과 속도를 따로 주려면 별도 파트여야 한다") 중
    속도 쪽이 작동하지 않고 있었다.

    수정: 배치가 파트 시작점을 포함하지 않으면 batchPoints[0] 의 speed/vel_mode 를
    그 파트 첫 포인트 값으로 덮는다. 파트 안의 속도가 모두 같으면 아무것도
    바뀌지 않는다. 교정이 실제로 일어나면 welding.batch.speedFromPartStart 로 찍는다.

    weaving_type 은 건드리지 않았다. robot-core 가 그걸로 고르는 두 계수
    (WELD_BATCH_SPEED_SCALE_VERTICAL / _HORIZONTAL)가 지금 둘 다 0.431 로 같다.

[3] 중심선이 용접과 반대 방향으로 누적됐다 (표시만)
    UcellSelect/index.tsx

    PART_ENABLE_GROUPS 의 수직 묶음을 ['p1','p2','p3','p4'] 로 적었는데 실제
    용접은 P4 -> P1 이다. useSchematicCalculations 가 이 순서대로 중심선 점을
    누적하므로 거리 숫자가 반대 끝에서 세어지고 구간 라벨이 뒤집힌다.

    이동 좌표와 터치 보정 보간은 start/end/ratio 가 서로 맞아떨어져 영향이 없다.
    클릭했을 때 로봇이 가는 자리는 정상이었다. 툴팁 거리와 로그 문구만 틀렸다.

    수정: 묶음 1·3 을 ['p4','p3','p2','p1'], ['p10','p9','p8','p7'] 로 뒤집는다.
    다른 소비처(getExecutableParts 의 every, partSavedPointCounts, partOrderMap)는
    전부 순서를 보지 않는다.

[4] robot-core 버전 문자열 동기화
    robot_core_all.cpp 의 APP_VERSION_STRING 이 1.1.227 로 남아 있어 설정 화면의
    '시스템 버전'이 프런트 버전과 달라 보였다. 1.1.230 으로 맞춘다.
    robot-core 로직 변경은 없다.

[DB]
    변경 없음. 012 마이그레이션을 이미 적용했다면 그대로 둔다.

[현장 확인 항목]
  - 우측 수평 끝(P12) -> 우측 모서리(P10) 전환에서 홈을 경유하는지.
    로그 welding.partTransition.retract 에 '횡단' 문구와
    welding.partTransition.approachCorner 가 찍히면 정상. code=185 가 없어야 한다.
  - welding.batch.speedFromPartStart 가 찍히는지. 찍히면 속도 교정이 실제로
    일어난 것이고, 안 찍히면 파트 안 속도가 모두 같다는 뜻이다.
  - 모서리 속도를 P4 에서 조절했을 때 실제로 느려지는지(예상 소요 20mm / 속도).
  - 중심선 점에 마우스를 올렸을 때 거리 숫자가 모서리 기준으로 세어지는지.
  - 설정 화면 '시스템 버전'이 1.1.230 인지.
