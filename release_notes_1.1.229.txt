v1.1.229 - 모서리 파트 후속 (블록 파라미터 · 모서리 기본값 · 화면 표시)

v1.1.228 로 파트 구조를 바꾼 뒤 남아 있던 세 가지를 정리한다.
228 exe 를 이미 설치했다면 이 버전으로 덮어쓸 것. 특히 1번은 파라미터를 잘못
적용하게 만드는 버그라 228 에서 블록 적용을 쓰면 안 된다.

구조 자체(파트 6개, 포인트 역할, 크레이터 판정, p11 접근 방향)는 228 그대로다.
DB 마이그레이션(012)도 228 에서 이미 적용했다면 다시 돌릴 필요 없다.

1. 블록 파라미터 적용 수정 (UcellSelect/index.tsx, useWeldingHandlers.ts)
   이어지는 자리의 포인트는 두 파트에 함께 들어간다(모서리 끝 P3/P9 가 수직
   파트의 시작점이다). 두 군데가 깨졌다.

   - getBlockPointIds 가 배열에서 먼저 나오는 파트를 돌려줬다. 실행 순서상
     모서리가 앞이라 P3 을 집어도 모서리 블록이 잡혔다. '그 포인트가 시작점인
     파트'를 우선 찾도록 바꿨다. 이제 P3 -> 수직 블록, P4 -> 모서리 블록.
   - 블록 적용이 다른 파트의 시작점을 덮었다. P4 에서 모서리 블록을 적용하면
     P3 도 모서리 조건이 되어 수직 파트 전체가 모서리 조건으로 돈다. 다른
     파트의 시작점은 건너뛰고, 건너뛴 포인트를 알림에 적어준다.

   결과: 파트 6개가 각각 독립 블록이다. 적용 순서를 신경 쓸 필요가 없다.

2. 모서리 포인트 기본값 (UcellSelect/index.tsx)
   P4/P10 은 227 까지 수평 파트의 시작점이어서 기본값이 plane_triangle +
   수평 위빙 + 26cpm/32V/290A 였다. 모서리는 수직선을 타는 용접이므로
   vertical_triangle + 새 CORNER_WEAVE_PARAMS + 16cpm/28V/250A 로 바꿨다.
   CORNER_WEAVE_PARAMS 는 수직 기본값에서 폭만 3.0 -> 5.0 으로 넓힌 출발값이고
   실측으로 맞춰야 한다.
   이 기본값은 새로 티칭을 시작할 때만 들어간다. 저장된 작업을 불러오면
   teaching_points 의 값이 덮으므로, 기존 작업에서는 화면에서 직접 고쳐야 한다.
   포인트 이름도 역할에 맞게 바꿨다(P4 좌측 모서리, P5 하단 좌측 시작 등).

   참고: robot_settings.min_weaving_distance 가 50mm 인데 모서리 구간은 20mm 라
   welding.weaving.shortSegment 경고가 로그에 찍힌다. 경고만 남기고 위빙은 그대로
   진행하며(weldingExecution 629행), robot-core 도 이 값을 SDK 로 넘기지 않는다.
   정상이다.

3. 화면 표시를 새 구조에 맞춤
   - useSchematicCalculations: 눈금자 배치를 바꿨다. 좌측 세로는 P1->P2->P3->P4
     (P4 가 모서리, 맨 아래), 좌측 바닥은 P5->P6. 우측도 같은 방식.
     227 까지는 세로가 P1~P3, 바닥이 P4~P6 였다.
     P2/P3 와 P8/P9 는 실제 TCP 거리 비율로 눈금자 위에 보간한다.
   - useSchematicCalculations: 중심선도 PART_ENABLE_GROUPS 로 그린다. 예전에는
     WELDING_PARTS(실행 기본값)로 그려서 P4 가 바닥 선에 끼어 꺾였다.
   - useSchematicCalculations: 중간점이 끝점과 최소 간격(30, 도식 좌표 단위)을
     유지하게 했다. 모서리 20mm 는 눈금자 550mm 의 3.6% 라 P3 가 P4 를 덮는데,
     포인트 동그라미는 클릭·드래그 대상이라(useDragAndDrop) 겹치면 집을 수 없다.
     고정 위치가 아니라 최소 간격이므로, P3 를 모서리+200mm 로 잘못 교시하면
     비율 0.64 라 그대로 그려진다. 그림이 교시 실수를 보여주는 역할은 남는다.
     실제 거리는 치수선이 보여준다.
   - DimensionLinesLayer: 치수선 묶음을 P5-P6 / P4-P3-P2-P1 / P11-P12 /
     P10-P9-P8-P7 로. 세로가 3구간, 바닥이 1구간이 된다.
   - UnifiedWorkspaceCanvas: 체크박스 실행 순서 배지를 묶음 순위로 바꿨다.
     part_index -> execution_order 를 그대로 쓰던 식이라 파트 6 / 체크박스 4 가
     되면서 배지가 1, 3, 4, 6 으로 건너뛰었다(2, 5 는 화면에 없는 모서리 파트).
     묶음별 최소 execution_order 로 정렬해 순위를 매겨 1, 2, 3, 4 로 나온다.
     DB 가 예전 4파트면 points 가 묶음에 안 맞아 part_index 로 떨어진다.
   - partSavedPointCounts 를 PART_ENABLE_GROUPS 기준으로. WELDING_PARTS 를 쓰면
     체크박스 묶음이 둘로 갈려 드리프트한다.
