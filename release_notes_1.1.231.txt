v1.1.231 - 파트 구성을 화면 진입 시 읽는다 (블록 적용이 옛 묶음을 쓰던 문제)

[증상]
P10 에서 '블록 적용'을 누르면 P10·P11·P12 가 같이 바뀐다.
새 구성의 모서리 우 파트는 [P10,P9] 이므로 P10 과 P9 만 바뀌어야 한다.
(2026-10-08 현장 확인)

[원인]
setWeldingPartOrder() 가 startWelding() 안에서만 불렸다. 즉 DB 의 파트 구성은
용접(또는 Dry Run)을 한 번 시작해야 메모리에 올라갔다.

그 전까지 getWeldingParts() 는 DEFAULT_WELDING_PARTS, 즉 012 마이그레이션 이전의
4파트 구성을 돌려준다.

  구 4파트 : [P4,P5,P6] [P3,P2,P1] [P10,P11,P12] [P9,P8,P7]
  신 6파트 : [P5,P6] [P4,P3] [P3,P2,P1] [P11,P12] [P10,P9] [P9,P8,P7]

그래서 getBlockPointIds('p10') 이 [P10,P11,P12] 를 돌려줬다. getPartStartPointIds()
도 같은 이유로 옛 시작점(P4,P3,P10,P9)을 돌려주니 P11·P12 가 보호 대상에서 빠져
그대로 덮어써졌다.

용접 실행 경로는 startWelding 이 직접 DB 를 읽으므로 영향이 없었다. 화면의
'블록 적용'과 '블록 이름'만 옛 묶음으로 동작했다.

[수정]
UcellSelect 화면과 펜던트 화면 진입 시 getWeldingPartOrder() 를 읽어
setWeldingPartOrder() 로 올린다. 실패하면 기존대로 기본 4파트로 동작하고
경고만 남긴다(UcellSelect 는 mount.partOrder / mount.partOrder.fail 로그).

[이미 덮어쓴 값 되돌리기]
이 버전을 깔기 전에 P10 블록 적용을 누르셨다면 P11·P12 에 모서리 값
(16cpm / 28V / 250A / vertical_triangle / 폭 5.0)이 들어가 있다.
수평 값으로 되돌려야 한다. 둘 중 하나로 하면 된다.

  - 펜던트에서 '갭 조회'로 시작. PART_GAP_MAP 은 이 버그와 무관하게 늘 옳은
    묶음을 쓰므로 P11·P12 에 수평 파라미터가 다시 들어간다.
  - 또는 P11·P12 를 화면에서 직접 수정
    (26cpm / 32V / 290A / plane_triangle / 폭 1.5, 좌우 5.0, 체류 0·300)

[같이 들어간 것 - 블록 적용 알림 문구 정리]
건너뛴 포인트를 알림에 적지 않는다. 작업자에게 필요한 건 "어디에 들어갔는지"이고,
"저 포인트는 다른 파트의 시작점이라 뺐다"는 내부 사정이다. 적용된 포인트만 적는다.
건너뛰는 동작 자체는 그대로다.

[확인]
P10 에서 블록 적용 -> "파트6 (모서리 우) (P10)에 파라미터가 적용되었습니다"
  (모서리 블록은 [P10,P9] 이고 P9 는 수직 파트의 시작점이라 보호된다)
P2 에서 블록 적용 -> P3·P1 이 바뀌어야 한다.
P11 에서 블록 적용 -> P12 만 바뀌어야 한다.
