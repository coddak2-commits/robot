v1.1.233 - 와이어 수동 조그 송급량 재보정 (뜨거운 쪽)

와이어 수동 조절에서 요청한 mm 와 실제 나가는 길이가 또 벌어졌다. 송급에
엔코더가 없어 실제 길이를 되먹임할 방법이 없으므로, 두 점 이상 실측해서
시간-길이 직선을 다시 구하는 방식 그대로 맞춘다.

[실측 (2026-10-08)]
    218 값(지연 7ms, 7.54mm/s)으로 용접 전후 두 번 측정했다. 두 번 모두
    마지막 아크에서 5분 안이라 뜨거운 프로파일로 돌았다.

      요청      명령 시간    용접 전    용접 후    평균
      1mm        140ms       2mm        3mm       2.5mm
      5mm        670ms       9mm        6mm       7.5mm
      25mm      3323ms      35mm       35mm      35mm

    세 점을 최소제곱으로 맞추면
      L(mm) = 0.86 + 10.26 x t(s)        (세 점 모두 오차 0.3mm 이내)

    두 가지가 읽힌다.
    - 속도가 7.54 -> 10.26mm/s 로 빨라졌다. 롤러 압력·라이너·스풀이 바뀌면
      드리프트한다고 208/218 노트에 적어둔 그대로다.
    - 길이와 무관하게 +0.9mm 가 늘 붙는다. 모터를 끈 뒤 와이어가 관성으로 더
      나가는 양으로 보인다. 지연이 양수면 짧은 펄스에서 '덜' 나가야 하는데
      실측은 반대로 더 나왔다(140ms 에 2.5mm = 17.9mm/s).

[수정]
    robot-front/src/lib/wireFeed.ts 의 WIRE_FEED_PROFILE_HOT.forward

      지연   7ms   ->  -84ms
      속도   7.54  ->  10.26 mm/s

    공식(duration = deadTime + (mm/speed)*1000)은 그대로다. 관성분 +0.86mm 를
    음수 지연 -84ms(0.86 / 10.26 * 1000)로 환산해 넣었다.

    검산
      25mm -> 2353ms -> 0.86 + 24.1 = 25.0mm
       5mm ->  403ms -> 0.86 +  4.1 =  5.0mm
       1mm ->   13ms -> 0.86 +  0.1 =  1.0mm

    1mm 는 펄스가 13ms 라 사실상 '모터 ON 후 바로 OFF' 이고, 실제 나가는 양은
    HTTP 왕복 시간이 정한다. 종전과 같이 1mm 는 +-1mm 가 한계다.

[안 고친 것]
    식은 쪽(WIRE_FEED_PROFILE_COLD)은 이번에 재지 않았다. 208 값
    (306ms, 6.56mm/s)이 그대로다. 5분 넘게 쉰 뒤 첫 조그는 여전히 안 맞을 수
    있다. 뜨거운 쪽이 36% 빨라졌으니 식은 쪽도 비슷하게 틀어졌을 가능성이 있다.
    맞추려면 5분 이상 쉰 상태에서 5mm·25mm 를 실측해야 한다.

    당기기(reverse)도 160 값(220ms, 23.4mm/s) 그대로다. 두 상태 모두 안 쟀다.
